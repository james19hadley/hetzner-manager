# Архитектура и Состояние Сервера (SERVER_ARCHITECTURE.md)

В этом документе приведена полная карта системного ландшафта нашего VPS-сервера в Hetzner (`65.21.57.159`), включая запущенные службы, концепцию безопасности, разделение прав пользователей и сетевую конфигурацию.

---

## 🎯 Парадигма Управления и Безопасности

Мы придерживаемся следующих ключевых принципов при работе с этим сервером:

1.  **Infrastructure as Code (IaC) / Local-First**:
    *   Все изменения конфигураций, скриптов и кода ботов вносятся локально на ноутбуке разработчика.
    *   Применение изменений на сервере происходит через локальный запуск скриптов развертывания (например, `deploy.sh` в проектах `hetzner-manager` и `ag2r`).
2.  **Понижение привилегий (Privilege Demotion / Non-root)**:
    *   Ни один веб-интерфейс или бот не должен запускаться от имени суперпользователя `root`.
    *   Каждому компоненту выделен свой изолированный системный пользователь с минимально необходимым набором прав.
3.  **Сетевая безопасность и VPN (Tailscale)**:
    *   Файрвол UFW блокирует любые административные и диагностические порты из публичной сети.
    *   Доступ к дашборду Netdata и другим внутренним API осуществляется исключительно через виртуальную частную сеть **Tailscale VPN** (интерфейс `tailscale0`, IP сервера: `100.103.212.83`).

## 🖥️ Что запущено на сервере

Наши приложения разделены на две группы: **системные службы на хосте** (управляются через `systemd`) и **изолированные сервисы в контейнерах** (управляются через `docker-compose`).

### 1. Системные службы (Systemd)
Запущены непосредственно на операционной системе хоста (Ubuntu 24.04):

| Имя службы | Описание | Пользователь | Порты / Ресурсы |
| :--- | :--- | :--- | :--- |
| `ag2r.service` | Удаленный веб-клиент для Antigravity | `ag2r` | Порт `3000` (HTTPS) |
| `xvfb.service` | Виртуальный X-сервер (дисплей `:99`) | `antigravity` | Переменная `DISPLAY=:99` |
| `antigravity-gui.service` | Electron-приложение Antigravity | `antigravity` | Подключается к Xvfb `:99` |
| `hetzner-bot.service` | Telegram-бот для мониторинга сервера | `tg-monitor` | Опрашивает Docker и systemctl |
| `netdata.service` | Агент мониторинга системы и предупреждений | `netdata` | Порт `19999` (только Tailscale/localhost) |

### 2. Контейнеры (Docker)
Используются для запуска изолированных ботов и их окружения. Все они находятся в статусе `Up` и работают стабильно:

*   **pulse_caddy** (`caddy:2-alpine`) — веб-сервер Caddy. Направляет входящий трафик (порты 80/443), раздает статику и проксирует домены.
*   **pulse_bot** (`pulse-monolith-bot-bot`) — основной Python-бот Pulse, работающий с базой данных PostgreSQL.
*   **pulse_worker** (`pulse-monolith-bot-worker`) — фоновый Celery-воркер для выполнения асинхронных задач Pulse.
*   **pulse_postgres** (`postgres:15-alpine`) — база данных PostgreSQL 15, используемая проектом Pulse.
*   **pulse_redis** (`redis:7-alpine`) — брокер очередей Redis 7 для Celery и кэширования.
*   **gemini_bot** (`tg-gemini-bot-bot`) — отдельный бот, общающийся с API Gemini.
*   **chinese_bot** (`ch_bot-bot`) — бот для изучения китайского языка.

## 🔑 Учетные записи и Права (Sudoers)

Для реализации безопасного взаимодействия между службами без использования root-прав настроена следующая система прав:

1.  **Пользователь `ag2r`** (владеет `/opt/ag2r/`):
    *   Имеет беспарольное право `sudo` на запуск, остановку и опрос службы GUI:
        `ag2r ALL=(ALL) NOPASSWD: /usr/bin/systemctl start antigravity-gui.service, /usr/bin/systemctl stop antigravity-gui.service, /usr/bin/systemctl is-active antigravity-gui.service`
    *   Это позволяет веб-интерфейсу усыплять и будить агента через кнопки на экране, не имея доступа к остальной системе.
2.  **Пользователь `tg-monitor`** (владеет `/opt/hetzner-manager/`):
    *   Добавлен в системную группу `docker`, что позволяет ему выполнять любые команды `docker ps` и `docker restart` без sudo.
    *   Имеет беспарольное право `sudo` на перезапуск ключевых служб:
        `tg-monitor ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart ag2r.service, /usr/bin/systemctl restart antigravity-gui.service, /usr/bin/systemctl restart xvfb.service, /usr/bin/systemctl restart hetzner-bot.service`
    *   Это позволяет Telegram-боту перезапускать зависшие службы при вызове команд `/restart_daemon`.

## 📡 Сетевая Конфигурация и Файрвол (UFW)

Настройки файрвола UFW на хосте:
*   `22/tcp` (SSH) — разрешен глобально (для удобства работы и деплоя).
*   `80/tcp`, `443/tcp` (HTTP/HTTPS) — разрешены глобально (для Caddy и веб-ресурсов).
*   `19999/tcp` (Netdata Dashboard) — **ЗАБЛОКИРОВАН** для внешнего мира. Доступ разрешен только для трафика с интерфейса `tailscale0`.
*   Порт `3000` (AG2R HTTPS) — разрешен для Tailscale / локального использования.
