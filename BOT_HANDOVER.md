# Передача контекста по Telegram-боту (Handover)

Этот файл создан агентом Antigravity из проекта `ag2r` для того, чтобы ты (новый агент Antigravity, работающий в проекте `hetzner-manager`) сразу понял текущую архитектуру, статус интеграции Telegram-бота и мог продолжить работу без лишних вопросов.

---

## 🚀 Что было сделано и текущий статус

Ранее Telegram-бот для мониторинга сервера жил в отдельном репозитории `tg-agy-client` и запускался в Docker-контейнере. Это приводило к конфликтам сессий (TelegramConflictError) и неудобству поддержки.

Мы провели полную интеграцию бота в этот проект:
1.  **Локальная папка бота**: Все исходники перенесены в директорию `bot/` в корне этого репозитория. Старый репозиторий `tg-agy-client` и его файлы полностью удалены.
2.  **Запуск службы на хосте**: Бот теперь работает напрямую на хосте сервера (VPS Hetzner) как служба **systemd** под названием `hetzner-bot.service`.
3.  **Безопасность (Privilege Demotion)**:
    *   Служба бота запускается от имени выделенного непривилегированного пользователя `tg-monitor`.
    *   Пользователь `tg-monitor` добавлен в группу `docker`, чтобы опрашивать докер-состояние.
    *   В `/etc/sudoers.d/tg-monitor` прописано правило беспарольного вызова `sudo systemctl restart` только для 4-х служб: `ag2r.service`, `antigravity-gui.service`, `xvfb.service` и `hetzner-bot.service`.
4.  **Устранение багов**:
    *   Старый контейнер `tg_agy_client_bot` на сервере полностью остановлен и удален.
    *   Решена проблема с путями импорта `ModuleNotFoundError: No module named 'src'`. Теперь служба запускается через модуль: `python3 -m src.main` с правильной рабочей директорией `/opt/hetzner-manager/bot`.
    *   Перенесены БД пользователей `data/bot_state.db` и файл конфигурации `.env`. Бот успешно авторизует владельца.

## 🛠️ Как это работает сейчас

### Деплой изменений
Весь проект `hetzner-manager` управляется с ноутбука по принципу IaC (Infrastructure as Code).
Если ты вносишь любые изменения в код бота (`bot/src/...`) или требования (`bot/requirements.txt`):
1.  Внеси изменения в файлы локально на ноутбуке.
2.  Запусти скрипт `./deploy.sh` в корне проекта. Он автоматически синхронизирует файлы по rsync, обновит зависимости в venv на сервере, обновит конфигурацию службы systemd и перезапустит `hetzner-bot.service`.
3.  Запушь изменения в git (`git push origin main`).

### Доступные команды в боте
*   `/start` или `/help` — приветствие и список всех доступных команд.
*   `/status` или `/sysinfo` — метрики CPU, RAM, диска, Uptime и Load Average.
*   `/services` или `/daemons` — опрос системных служб `ag2r`, `antigravity-gui`, `xvfb` и `hetzner-bot`.
*   `/containers` or `/docker` — список запущенных Docker-контейнеров на сервере.
*   `/restart_daemon <name>` — безопасный перезапуск разрешенных служб (через настроенный sudoers).
*   `/restart_container <name>` — перезапуск Docker-контейнера.
*   `$ <команда>` — выполнение произвольной консольной команды на хосте VPS (доступно только для верифицированных в БД Telegram ID).

#### 🤖 Управление и Мониторинг Antigravity
*   `/agy_status` — детальный опрос состояния служб (`xvfb`, `antigravity-gui`, `ag2r`), опрос CDP контекстов на порту `9000`, снятие скриншота виртуального дисплея `:99` через `scrot` и отправка снимка в Telegram.
*   `/agy_restart` — перезапуск службы `antigravity-gui.service` через sudo.
*   `/agy_sleep` — перевод Antigravity в режим сна (остановка `antigravity-gui.service`).
*   `/agy_wakeup` — пробуждение Antigravity (запуск `antigravity-gui.service`).
*   `/agy_logs` — получение последних 15 строк логов `journalctl` для `antigravity-gui.service` и `ag2r.service`.

## 📋 План будущих задач по боту

Если пользователь попросит тебя продолжить улучшение бота, обрати внимание на следующие задачи:
1.  **Интеграция с Netdata API**: Бот сейчас считывает системные метрики простыми утилитами Linux (`uptime`, `free`, `df`, `top`). Можно переписать сбор метрик на получение детальных метрик с локального Netdata API (`http://localhost:19999/api/v1/allmetrics?format=json`).
2.  **Уведомления об алертах**: Настроить бота, чтобы он отправлял оповещения о критических событиях на сервере (высокая нагрузка, падение докер-контейнеров) напрямую в Telegram в реальном времени (в дополнение к текущим email-алертам msmtp).
3.  **Логирование**: Настроить логирование ошибок бота в файл внутри `bot/data/` или вывод в syslog.

Удачи в разработке!
