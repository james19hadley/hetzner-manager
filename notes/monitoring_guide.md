# Руководство по мониторингу и деплою сервера Hetzner

В этом документе описана архитектура системы мониторинга, развернутой на VPS, а также инструкции по управлению проектом `hetzner-manager`.

---

## 🧭 Архитектура системы

1. **Netdata (Агент мониторинга)**: Установлен на хосте VPS. Собирает более 4000 метрик в реальном времени.
2. **UFW (Файрвол)**: Настроен так, что порт Netdata (`19999`) заблокирован для внешнего мира и доступен только внутри приватной сети **Tailscale VPN** (интерфейс `tailscale0`).
3. **msmtp (Почтовый клиент)**: Легковесный SMTP-клиент, настроенный как системная служба отправки почты. Пересылает локальные письма через ваш Gmail SMTP-аккаунт.
4. **Cron (Планировщик)**: Запускает регламентные задачи на сервере (например, еженедельные отчеты).

## 🔔 2. Управление алертами (Оповещениями)

Все критические алерты отправляются на вашу почту автоматически, даже если ваш ноутбук выключен.

### Скрипт быстрой настройки:
Если вам нужно изменить почту отправления или пароль приложения, выполните на ноутбуке:
```bash
ssh -t root@100.103.212.83 "bash /tmp/setup_alerts.sh"
```
Скрипт в интерактивном режиме запросит новые данные, применит их и отправит тестовое письмо.

### Ручное редактирование конфигураций на сервере:
*   Настройки SMTP-сервера и паролей: `/etc/msmtprc`
*   Настройки получателей алертов Netdata: `/etc/netdata/health_alarm_notify.conf`

## ⚙️ 3. Как вносить изменения и деплоить (Разработчику)

Проект `hetzner-manager` следует методологии **Infrastructure as Code (IaC)**. Ноутбук является единственным источником правды.

Если вы хотите изменить настройки (например, добавить новые алерты, поменять логику отчетов, изменить периодичность сбора метрик):

1.  **Внесите изменения локально** на ноутбуке в файлы в папках `configs/` или `scripts/`.
2.  **Запустите деплой** в консоли ноутбука:
    ```bash
    ./deploy.sh
    ```
    Скрипт автоматически:
    *   Создаст нужные директории на сервере.
    *   Синхронизирует файлы проекта через `rsync` по SSH/Tailscale.
    *   Скопирует конфигурации Netdata в системные папки сервера.
    *   Перезапустит службу Netdata для применения настроек.
    *   Обновит задачи планировщика `cron` на сервере.
3.  **Запушьте изменения в репозиторий**:
    ```bash
    git add .
    git commit -m "Описание изменений"
    git push
    ```

## 📈 4. Проверка состояния через консоль (CLI)

Вы можете быстро узнать, как чувствует себя сервер, не открывая браузер. Находясь в папке проекта на ноутбуке, выполните:
```bash
./scripts/server_status.py
```
Скрипт сделает запрос к API Netdata по Tailscale и выведет общую информацию, аптайм и активные предупреждения (алерты) прямо в терминал.

## 📅 5. Еженедельные отчеты (Weekly Health Reports)

Каждое **воскресенье в 18:00** сервер отправляет на ваш email отчет со средней статистикой нагрузки за неделю.
*   **Скрипт отчета на сервере**: `/opt/hetzner-manager/scripts/weekly_report.py`
*   **Логи выполнения отчетов на сервере**: `/var/log/weekly_report.log`

Чтобы запустить и проверить отправку отчета вручную в любое время, выполните:
```bash
ssh root@100.103.212.83 "python3 /opt/hetzner-manager/scripts/weekly_report.py"
```

## 🌐 6. Будущее добавление блога (Caddy)

На сервере в Docker-контейнере `pulse_caddy` работает веб-сервер Caddy. Чтобы разместить на нем ваш сайт/блог:

1.  **Создайте папку** для файлов блога на сервере:
    ```bash
    ssh root@100.103.212.83 "mkdir -p /var/www/blog"
    ```
2.  **Пробросьте её в Caddy**: В файле `/opt/pulse-monolith-bot/docker-compose.yml` в разделе volumes службы `caddy` добавьте:
    ```yaml
    - /var/www/blog:/var/www/blog:ro
    ```
3.  **Настройте домен**: В файле `/opt/pulse-monolith-bot/Caddyfile` пропишите:
    ```caddy
    blog.yourdomain.com {
        root * /var/www/blog
        file_server
        encode gzip
    }
    ```
4.  **Перезапустите Caddy**:
    ```bash
    cd /opt/pulse-monolith-bot
    docker compose up -d --remove-orphans
    docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile
    ```
